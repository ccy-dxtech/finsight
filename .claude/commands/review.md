이 프로젝트의 변경 사항을 리뷰하라.

리뷰 범위: $ARGUMENTS
(범위가 비어 있으면 `main...HEAD`를 리뷰한다. `git diff --stat <범위>`로 바뀐 파일부터 확인한다.)

먼저 다음 문서들을 읽어라:
- `/AGENTS.md` (CLAUDE.md는 이 파일을 가져온다)
- `/docs/ARCHITECTURE.md`
- `/docs/ADR.md`
- 화면 파일(`src/app/**`, `src/components/**`, `globals.css`)이 바뀌었으면 `/docs/UI_GUIDE.md`, `/docs/UX_GUIDE.md`, `/docs/design-system/README.md`

그런 다음 변경된 파일들을 확인하고, 아래 체크리스트로 검증하라:

## 체크리스트

1. **아키텍처 준수**: ARCHITECTURE.md에 정의된 디렉토리 구조를 따르고 있는가?
2. **기술 스택 준수**: ADR에 정의된 기술 선택을 벗어나지 않았는가?
3. **테스트 존재**: 새로운 기능에 대한 테스트가 작성되어 있는가?
4. **CRITICAL 규칙**: AGENTS.md의 CRITICAL 규칙을 위반하지 않았는가?
5. **빌드 가능**: 빌드 명령어가 에러 없이 통과하는가?
6. **화면 규칙**: UI_GUIDE와 디자인 시스템을 따르는가? (`@theme` 토큰만 사용, 한국어·해요체 문구, 한 화면에 초록 버튼 하나, 결제 버튼 근처 테스트 결제 문구)
7. **사용자 여정**: UX_GUIDE "상태별 다음 행동"대로 빈·오류·소진·잠금·결제 직후 상태마다 다음 행동이 있는가? "PR 점검 목록"을 지키는가? "현재 구현 점검과 개선 제안" 표에 이번 변경과 관련해 열린 항목이 있는가?
8. **문서·E2E 동기화**: 바뀐 동작이 PRD(화면 설명, "한계")·ARCHITECTURE·UI_GUIDE·UX_GUIDE(상태 표의 "(있음)" 포함)와 `tests/e2e` 시나리오에 반영됐는가?

화면 파일이 바뀌었고 Agent 도구를 쓸 수 있으면 7번은 `ux-reviewer` 에이전트에게 바뀐 화면 파일 목록을 넘겨 맡긴다.
에이전트의 지적은 그대로 옮기지 말고 하나씩 코드에서 확인한 뒤 표에 넣는다.

외부 SDK(Polar, Supabase, Anthropic)의 필드나 동작에 대한 지적은 `node_modules`의 실제 타입·코드로 확인한 뒤에만 적는다.
예: Polar `/2026-10` 웹훅 payload는 `product_id`, `customer.external_id`처럼 snake_case다.
